# Progressive Reader app audit — 2026-09-08

Scope: signed-in desktop web app at https://progressivereader.net and the current frontend checkout (5f47bba2). Inspected Library, Vocabulary, Grammar, Clipboard, JLPT dashboard, Settings, and a Japanese EPUB. This is an audit, not an implementation change. Android, mobile breakpoints, new uploads, paid translation requests, and a complete exam attempt were not exercised. Production was not verified to match the checkout exactly; its reader uses page labels where the checked-out dock uses chapter labels.

The app's half-finished feeling comes mainly from disconnected data and workflows. The newer library and settings UI is coherent, but the study pages have different visual conventions, setup requirements, and definitions of progress. Repair the reading/import loop first, then unify study state and presentation.

## Fix first

### 1. Embedded EPUB contents links leave the book and break reading — P1, reproduced live

Opened リラの花咲くけものみち. Its embedded contents page contains links such as `p-006.xhtml#toc006`. Clicking chapter six navigated the browser to `/book/p-006.xhtml#toc006`, then showed “Error loading book: Book not in library. Return to library and try again.” The reader continued showing “Laying out pages…” in the error state.

Resolve EPUB-relative links against the publication's spine/navigation and select the target chapter/anchor inside the current book. Keep actual external links distinct. On loading failure, replace the progress label with a stable error state and recovery action.

Source lead: `frontend/src/features/reader/utils/htmlToJsx.tsx:98` preserves ordinary href attributes, and line 143 creates their native elements. The displayed reader content needs an internal-link handler. Add an interaction test with a real relative chapter link and fragment, not only TOC-title extraction.

### 2. The clipboard text box accepts edits that the reader and save action ignore — P1, reproduced live and confirmed in source

Typed `Audit text: 日本語の文章です。` into the visible text area. The input displayed it, while the header still said “No clipboard text yet.” The textarea has only `onPaste`; it has no `onChange` connection to reader state. Saving reads `entries`/`rawText`, not the textarea. Consequently, manual input is ignored, and edits after a paste can leave the saved content different from what is visible.

Source: `frontend/src/features/clipboard/components/ClipboardReader.tsx:497` and `:280`.

Use a controlled draft and explicit “Read text”/“Add text” action, or consistently synchronize editing with the current entry. Disable Save when there is no content or a save is in flight. Keep advanced clipboard polling options secondary to the basic paste/read/save flow.

### 3. Vocabulary totals contradict each other across pages — P1 product consistency issue, reproduced live

Library showed 1,330 mastered words and 0 saved words. Vocabulary showed 0 total, 0 mastered, 0 learning, and “No vocabulary yet.” The JLPT page separately showed an N2 snapshot of 2,967/4,792 known words, last checked April 20.

These are different stores/scopes, not proof that words were deleted. Library reads the Drive-backed `vocabBank`; Vocabulary reads backend user vocabulary; JLPT reads deck snapshots. The UI does not make those distinctions clear enough, so opening Vocabulary makes existing progress appear lost.

Sources: `frontend/src/features/books/components/BookLibrary.tsx:90`, `frontend/src/features/vocabulary/components/vocabularyPage/hooks/useUserVocabulary.ts:32`, and `frontend/src/features/jlpt/services/jlptSelectors.ts`.

Define one study overview with clearly identified sources and timestamps. Reader-saved words need an obvious destination in Vocabulary. If these datasets intentionally stay separate, label them “Reader words”, “JPDB deck progress”, and “Manual vocabulary” rather than giving each a generic mastery total.

### 4. Continue Reading can show invented or chapter-only book progress — P2, confirmed in source

`readingProgressRatio` returns a fixed 10% when it has evidence of reading but lacks enough information to calculate progress. If scroll dimensions exist, it returns progress within the current chapter without incorporating the chapter index. A percentage on a book resume card therefore may not be whole-book completion.

The live resume card displayed 10%; this audit did not inspect its stored dimensions, so that particular value cannot be conclusively attributed to the fallback.

Source: `frontend/src/features/books/utils/libraryView.ts:19-33`.

Calculate book progress from chapter position plus within-chapter progress, or label chapter progress explicitly. Show “Started” or a location when progress is unknown instead of a fabricated percentage.

### 5. Expired JLPT goals generate absurd daily targets — P2, reproduced live and confirmed in source

On September 8, the dashboard still displayed the July 5 exam date, 0 days remaining, and an exam pace of 1,825 cards/day. `getDerivedDailyTarget` clamps the remaining days to at least one, assigning every remaining card to today after the exam has passed.

Source: `frontend/src/features/jlpt/services/jlptSelectors.ts:83-88`.

Introduce an expired/completed goal state. Stop deriving an exam pace after the date and present “Record result” or “Set next goal”. Make old snapshots visibly stale before using them for current recommendations. The persisted goal itself should not be changed without the user's choice.

## Make the app feel finished

### 6. Study screens use a different visual system — reproduced live

Library uses compact typography, restrained surfaces, and neutral actions. Vocabulary switches to large emoji headings, blue/green/orange stat numbers, and oversized gray panels. Clipboard adds blue and green actions and a full-width toolbar. Its footer is white even in dark mode.

Sources: `frontend/src/features/vocabulary/components/VocabularyPage.tsx`, the `vocabularyPage` panels, `frontend/src/features/clipboard/components/ClipboardReader.tsx`, and `frontend/src/shared/components/Footer.tsx:5`.

Apply the existing app theme tokens, spacing, buttons, and headings across these pages. Keep one primary action per state. Rename the generic “Test” navigation item to “JLPT”; explain the goal/dashboard page in learner terms rather than “JLPT Test Runner” and a local `JLPT_Tests` folder.

### 7. Grammar starts with a wall of already-known material — reproduced live; persistence bug confirmed in source

Grammar opened all 104 N5 entries despite every entry being known. Higher levels sat below that long list. There is no visible search or “Learning/Unknown” filter. Repeated disabled controls and “Too ambiguous for MVP mining” make the page read like an internal tool.

`loadOpenSections` also maps a saved empty array back to N5, so collapsing all sections cannot survive a remount.

Source: `frontend/src/features/grammar/components/GrammarPage.tsx:26-31`, `:269`.

Respect an intentionally empty saved selection; default to the active study level or learning items. Add search and status filters. Move the Background Miner controls into a secondary status area and replace implementation terminology with an explanation useful to a learner.

### 8. Vocabulary filters shrink their own options and totals — P2, source-confirmed

Language/mastery filters are sent to the backend. The returned, already-filtered collection is then used to derive both the language dropdown and headline totals. Selecting one language can remove the other language choices; selecting Mastered makes the headline Learning count zero regardless of the complete collection.

Source: `frontend/src/features/vocabulary/components/vocabularyPage/hooks/useUserVocabulary.ts:32`, `:84`, `:93`.

Keep overall stats and language choices independent of list filters. Fetch them separately or filter a complete local collection. Label result counts separately from overall progress.

### 9. Important controls are clickable divs — P2 accessibility issue, source-confirmed

Book covers/cards and the JPDB deck selector appear as generic containers in the accessibility tree. Their source implements mouse handlers without native link/button semantics or keyboard equivalents. Pointer users can open a book while keyboard users cannot activate that same primary card action normally.

Sources: `frontend/src/features/books/components/BookCardHover.tsx:308`, `frontend/src/features/vocabulary/components/DeckSelector.tsx:54` and `:112`.

Use a real book link with separate action buttons, and a keyboard-operable deck selector. Also fix the untranslated navigation accessible name `nav.jlptTestsPageAria`, which is visible in the live accessibility tree.

### 10. Library metadata pretends unknown chapter counts are one — reproduced live and source-confirmed

All observed cards, including novels and PDFs, displayed “1 ch”. `BookCardHover` uses `book.totalChapters || 1`. Unknown metadata is being rendered as a factual count, and PDFs receive a chapter label.

Source: `frontend/src/features/books/components/BookCardHover.tsx:701`.

Omit unknown counts, persist extracted EPUB counts, and use pages for PDFs. Text snippets and lyrics should not need book-like chapter metadata to look complete.

### 11. Authentication and recovery routes need completion — source-confirmed, not exercised signed out

`/sign-up/*` renders `SignedOutLayout`, which renders `SignInForm` and Clerk's `SignIn`; there is no dedicated SignUp component on that route. Study guards use “signed in OR books.length > 0”, conflating content availability with authorization and offline capability. They do not wait for auth/offline initialization. There is also no catch-all not-found route in App.

Sources: `frontend/src/App.tsx:48-57`, `:143`, `:250`; `frontend/src/shared/components/SignInForm.tsx`.

Provide the correct signup route, explicit loading/offline/signed-out states, capability-specific gating, and a useful unknown-route page. Confirm signed-out and offline flows separately before release; the signed-in browser audit does not establish their exact runtime behavior.

## Validation and limits

Failures: vocabulary due-card integration could not find “My Deck”; admin smoke could not find its header. The run also reported `ERR_INVALID_STATE` while consuming a response stream. These need investigation as test/runtime failures, not automatic attribution to production bugs.
- Test log: `.tmp/audit-tests.log`. The initial sandboxed attempt could not load the esbuild config; the unrestricted run completed and produced the counts above.
- TypeScript check with `tsc -p tsconfig.app.json --noEmit` ran out of heap at approximately 4 GB. No clean typecheck is claimed. Log: `.tmp/audit-types.log`.
- No application source, account settings, goals, vocabulary entries, or books were intentionally edited. Ordinary app visits and opening the book can run the app's normal sync/progress behavior. A disposable string was typed into Clipboard to verify its input bug; it was not saved.

Suggested sequence: fix EPUB link navigation and clipboard state; make progress truthful and vocabulary sources understandable; handle expired goals; then bring Vocabulary, Clipboard, Grammar, and the footer into the existing visual system. Add focused interaction coverage for these failures before expanding features.
